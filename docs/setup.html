Developer Setup Instructions

This guide is for developers who want to host their own instance of Event Sentinel. If you're a Discord server administrator looking to use the bot, see the Getting Started guide instead.

👨‍💻 Developer Guide: This page covers hosting your own bot instance. End users should use the Getting Started guide to configure the bot in their servers.

💡 Prefer a Hosted Solution? You can use our hosted instance - invite Event Sentinel to your server without any setup!

1. Discord Bot Setup

  1. Go to Discord Developer Portal
  2. Click "New Application" and give it a name
  3. Go to the "Bot" section and click "Add Bot"
  4. Under "Privileged Gateway Intents", enable:
    • Presence Intent
    • Server Members Intent
    • Message Content Intent
    • Direct Messages Intent (required for modmail functionality - must be enabled for modmail to work)
  5. Copy your bot token (keep this secure!)

2. Bot Installation

Create Environment File

Create a .env file based on .env.example:

cp .env.example .env

Add Bot Token and Configuration

Add your bot token and optional settings to the .env file:

DISCORD_TOKEN=your_bot_token_here
# Optional: Set custom bot status (format: playing:Game Name or watching:Something)
BOT_STATUS=watching:your servers

BOT_STATUS Format: You can set a custom bot status using the format type:message. Supported types: playing, watching, listening, streaming. If no prefix is provided, defaults to watching.

Create Configuration Files

Choose one of the following configuration methods:

# For simple config (optional)
cp config.example.json config.json

# OR for modular config (recommended)
cp -r config.example config

Install Dependencies

Install required Python packages:

pip install discord.py python-dotenv PyNaCl Flask aiohttp

Or use the requirements file:

pip install -r requirements.txt

3. Invite Bot to Server

Generate an invite URL with the following permissions:

  • View Channels
  • Send Messages
  • Embed Links
  • Attach Files
  • Read Message History
  • View Audit Log
  • Manage Webhooks (optional)

Required scopes: bot, applications.commands

Invite URL template (replace YOUR_BOT_CLIENT_ID with your bot's client ID):

https://discord.com/api/oauth2/authorize?client_id=YOUR_BOT_CLIENT_ID&permissions=412385476672&scope=bot%20applications.commands

4. Configure Log Channel

Once the bot is running:

  1. Use the /setlogchannel command in your Discord server (must be an administrator)
  2. Select the channel where you want events to be logged for that specific server
  3. Make sure the bot has permission to send messages in that channel
  4. If you add the bot to multiple servers, repeat this command in each server to set up logging

Note: Each server has its own independent log channel configuration!

Dashboard Control (Optional)

If you're running the bot in the support server, you can control the dashboard using:

  • /dashboard start - Start/enable dashboard routes (owner only, support server only)
  • /dashboard stop - Stop/disable dashboard routes

Health Check Endpoint: The /health endpoint is always available, even when the dashboard is disabled. This allows monitoring systems to check bot status without requiring dashboard access.

5. Running the Bot

Start the bot using one of these methods:

# Method 1: Direct execution
python main.py

# Method 2: Run as module (recommended)
python -m .

The bot will start and display:

  • Bot username and ID
  • Discord.py version
  • Current log channel (if configured)

Module Entry Point: The bot includes a __main__.py file that allows running it as a module with python -m .. This is the recommended method for production deployments.

Requirements

  • Python 3.11+
  • discord.py 2.4+
  • python-dotenv
  • PyNaCl
  • Flask 3.0+ (for dashboard)
  • aiohttp 3.9+ (for API requests)

Permissions Required

The bot needs these permissions to function properly:

  • View Audit Log (to capture moderator information)
  • View Channels
  • Send Messages
  • Embed Links
  • Read Message History

Architecture Overview

The bot uses a modular cog-based structure with the following key components:

  • main.py - Bot initialization and startup
  • __main__.py - Module entry point for running as python -m .
  • utils.py - Shared utility functions
  • rate_limiter.py - Rate limiting system to prevent Discord API errors
  • dashboard.py - Web dashboard (optional, can be toggled on/off)
  • cogs/ - Modular command and event handlers

The rate limiting system automatically prevents Discord API rate limit errors and works in the background without any configuration.

Troubleshooting

If you encounter issues, check:

  • Bot has correct permissions in the server
  • All required intents are enabled in the Developer Portal (including Direct Messages Intent for modmail - this is critical for modmail functionality)
  • Log channel is properly configured with /setlogchannel
  • Bot has permission to send messages in the log channel
  • If using modmail, ensure the modmail channel has proper permissions (Send Messages, Embed Links, Create Public Threads, Send Messages in Threads)
  • Bot token is correct in the .env file
  • If messages seem delayed, check /ratelimitstatus - they may be queued due to rate limits
