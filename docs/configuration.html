Configuration Guide

This guide covers both user-facing commands and advanced developer configuration options for Event Sentinel.

👥 For Server Administrators: Most configuration can be done using the /setlogchannel command. See the Getting Started guide for simple setup instructions.

Configuration Layouts

The bot supports two configuration layouts. The loader prefers the modular config/ layout if present, and falls back to the legacy config.json.

Preferred: config/ Directory (Modular)

This is the recommended configuration method. It organizes settings into separate files for better management.

File Structure

All files in the config/ directory are optional:

  • config/base.json - Global defaults
  • config/colors.json - Embed colors map
  • config/guilds.json - Per-guild log channels
  • config/toggles.json - Per-guild event toggles

Example: colors.json

Define custom colors for different event categories:

{
  "moderation": "0xE74C3C",
  "channel": "0x3498DB",
  "voice": "0x9B59B6",
  "message": "0x2ECC71",
  "server": "0xF39C12",
  "role": "0x3498DB"
}

Example: guilds.json

Map server IDs to their log channel IDs:

{
  "123456789012345678": 987654321098765432
}

Note: You can also use the /setlogchannel command to configure this automatically.

Example: toggles.json

Enable or disable specific events per server:

{
  "123456789012345678": {
    "voice": {
      "self_unmute": false
    }
  }
}

Legacy: config.json (Monolithic)

You may keep a single config.json with the combined structure. The bot will still read it if config/ is absent. The application also mirrors the composed configuration back to config.json when saving, for compatibility.

Multi-Server Support

The bot fully supports multiple Discord servers! Each server can have its own dedicated log channel, configured independently using /setlogchannel.

For Server Administrators:

When you add Event Sentinel to multiple servers:

  1. Run /setlogchannel in each server
  2. Select the desired log channel for that server
  3. Each server's configuration is stored separately

Note: You don't need to configure anything special - just run the command in each server and select the appropriate channel!

User Commands

These commands are available to Discord server administrators for configuring Event Sentinel.

/setlogchannel

The primary command for setting up Event Sentinel in your server.

  • Permission Required: Administrator
  • Usage: Type /setlogchannel and select a channel from the dropdown
  • Description: Configures which channel Event Sentinel will use to log events for the current server
  • When to use:
    • Initial setup - when first adding the bot to your server
    • Changing log channels - if you want to move logs to a different channel
    • Multi-server setup - run this command in each server you want to monitor
Step-by-step:
1. Type /setlogchannel in any channel
2. A channel selector will appear
3. Click on the channel where you want logs sent
4. The bot will confirm the channel has been set

✅ Important: Make sure the bot has permission to send messages in the channel you select. The bot needs "Send Messages" and "Embed Links" permissions in that channel.

Advanced Configuration (For Developers)

The following configuration options are for developers hosting their own bot instance. End users don't need to modify these files.

Architecture (Developer Information)

The bot uses a modular cog-based structure:

event-sentinel/
├── main.py # Bot initialization and startup
├── utils.py # Shared utility functions
├── config.json # Bot configuration
├── cogs/
│ ├── moderation.py # Member and moderation events
│ ├── voice.py # Voice channel events
│ ├── message.py # Message events
│ ├── server.py # Server and invite events
│ ├── roles.py # Role events
│ └── channels.py # Channel and thread events

Common Questions

How do I change the log channel?

Simply run /setlogchannel again and select a different channel. The bot will immediately start sending logs to the new channel.

Can I have different log channels for different event types?

Currently, Event Sentinel uses one log channel per server for all event types. All events will be sent to the channel you configure with /setlogchannel.

What if I remove the bot and add it back?

You'll need to run /setlogchannel again to reconfigure the log channel. The bot doesn't remember previous configurations after being removed.

Can I disable certain event types?

Currently, all event types are logged when enabled. Advanced event filtering may be available in future updates. For now, all configured events will be logged to your selected channel.

Error Handling

The bot gracefully handles:

  • Missing permissions - The bot will attempt to log events but may show limited information
  • Missing audit log entries - Some events may not include moderator information
  • Unavailable log channels - The bot will continue running but won't be able to send logs
  • Rate limiting - The bot automatically handles Discord's rate limits

If you notice events aren't being logged, check that:

  • The bot has permission to send messages in the log channel
  • The log channel is properly configured with /setlogchannel
  • The bot has "View Audit Log" permission in your server
